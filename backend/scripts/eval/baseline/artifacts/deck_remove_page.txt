## 問題定義

![](diagrams/diagram-9f902f429742.svg){.hub-diagram fig-align="center" fig-alt="diagram" data-font="20.3"}

- 串流語音辨識對人名、地名等罕見詞常常辨識錯誤
- 一般解碼的罕見詞錯誤率偏高
- 加入熱詞後的效果待驗證

::: {.takeaway}
目標：不重新訓練模型，讓使用者提供的熱詞更容易被辨識
:::

::: {.notes}
這一頁說明為什麼串流辨識對罕見詞特別困難，以及我們想在不重新訓練的前提下改善這個問題。串流語音辨識的使用者常會說出人名、地名等罕見詞，這些詞在訓練資料中出現次數很少，模型因此容易辨識錯誤。圖由左到右是：語音輸入含有罕見詞，經過串流 ASR 解碼後，輸出時罕見詞辨識錯誤，一般解碼的罕見詞錯誤率偏高（具體數字資料未提供，等熱詞實驗接上後一併測量報告）。加入熱詞後的效果是本簡報後續要驗證的重點：讓使用者能提供自己的熱詞，在不重新訓練模型的情況下提升這些詞的辨識率。
:::

## 動態熱詞的做法

![](diagrams/diagram-d568fd92d61c.svg){.hub-diagram fig-align="center" fig-alt="diagram" data-font="20.9"}

::: {.incremental}
- 熱詞加權作用在 RNN-T 解碼階段
- 調查做法：shallow fusion、TCPGen、contextual biasing
- 差別：熱詞資訊加在模型的哪個位置
:::

::: {.notes}
這頁整理動態熱詞在 Zipformer + RNN-T 系統中的整體流程。語音輸入先經過 Zipformer 編碼器取得聲學表徵，再交給 RNN-T 解碼。解碼階段會對熱詞做加權，最後輸出辨識結果。目前調查到的做法有三種：shallow fusion、TCPGen 與 contextual biasing。三者的差別不在熱詞內容本身，而在於熱詞資訊加在模型的哪個位置。
:::

## Idea card

![](diagrams/diagram-864e7fc2f138.svg){.hub-diagram fig-align="center" fig-alt="diagram" data-font="16.7"}

![](diagrams/diagram-3bba488d579c.svg){.hub-diagram fig-align="center" fig-alt="diagram" data-font="26"}

::: {.takeaway}
兩步驟：先離線建字首樹索引，解碼時對命中前綴的假設即時加分
:::

::: {.notes}
這頁是核心想法：把熱詞清單建成字首樹（trie），每個熱詞依字元展開成前綴路徑，樹離線建一次就能重複使用。RNN-T 解碼時，若目前假設的字尾在字首樹上命中某個前綴，就即時給該假設額外的加分。加分讓包含熱詞的路徑更容易留在 beam 內，最終輸出更偏向熱詞。字首樹的查詢每次只沿當前前綴走一步，額外成本很低，適合串流辨識的即時解碼。下方的示意圖把整個機制拆成兩個階段對照：離線階段只做一次，把使用者提供的熱詞清單建成字首樹索引；線上階段在串流解碼中反覆進行，前綴命中後即時加分，讓輸出偏向熱詞。圖中以高亮標出與既有做法的差異處：熱詞清單、字首樹與加分模組是本週新想法，與既有的 RNN-T 串流解碼串接，最後輸出偏向熱詞的結果。
:::

## 下週與要問

![](diagrams/diagram-7627f838270d.svg){.hub-diagram fig-align="center" fig-alt="diagram" data-font="20.9"}

- 下週：實作字首樹加分的 baseline
- 想問老師：罕見詞 recall 要用哪一份測試集

::: {.takeaway}
先用字首樹 baseline 立好比較基準，再和老師確認測試集
:::

::: {.notes}
下週的目標是把先前的想法做成 baseline：把熱詞清單建成字首樹，在 RNN-T 解碼時對熱詞路徑加分，先跑出一個可以比較的結果。有了這個 baseline，之後的動態熱詞方法才有明確的對照對象。另外想請教老師：評估罕見詞 recall 時應該用哪一份測試集，因為測試集的選擇會直接影響結果的解讀。確認測試集之後，baseline 的數字才有固定的比較標準。
:::
