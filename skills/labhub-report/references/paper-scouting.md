# 論文搜尋：從頂會找候選論文（貫穿，餵進論文報告/淺讀）

目的：在 INTERSPEECH、ICASSP、ASRU、SLT 等語音頂會裡，依目前進度（Table 1、idea card、one-pager 題目）或未來投稿方向，搜出一批候選論文，列成清單讓使用者自己挑要深讀、要報告的那一篇/幾篇。

**這個功能只做篩選，不做閱讀。** 輸出永遠是「候選清單」，不是論文報告。使用者選定要報的那篇之後，必須照 `paper-report.md` 的五步流程（餵PDF→AI生草稿→兩遍讀核對→自己寫7/12/13頁→核對紀錄）重新跑一次，不能拿這份清單的摘要式描述直接當報告內容——那只是讀過title/abstract層級的篩選，不是深讀。

## 什麼時候用

- 每週要選一篇報告，手上沒有候選，不知道讀什麼
- 教授給了方向，要掃一輪最近的會議看有沒有相關/competing work
- 寫 design doc 前要確認 Table 1 的 baseline 有沒有更新的版本
- Round 2 深挖路線的「12-18個月文獻盤點」要先拉候選清單
- 定期（例如每次大會議放榜後）掃一輪，看有沒有新方向值得做成 idea card

## 輸入：先搞清楚要找什麼，不要空泛搜「語音」

搜尋前先從使用者現有檔案抓關鍵字，不要自己發散亂猜：

| 關鍵字來源 | 在哪裡找 |
|---|---|
| 目前題目 | `design/〔題目〕_design_〔日期〕.md` 的一句話主張 |
| idea card 假設/最接近的prior work | `idea_log.md` |
| Round1/2 one-pager 的技術關鍵詞 | `_r1_checked.md`／`_r2_*.md` |
| 上次淺讀記錄的「動了哪一格」 | `notes/papers/reading_log.md` |

如果使用者沒有這些檔案或沒說清楚題目，先問：「要找的主題/任務是什麼？目前在用的方法或baseline是什麼？」不要用泛用關鍵字搜，搜出來的東西不會有用。

## 搜尋範圍

**預設會議**（可依題目調整增減）：

| 會議 | 性質 | 備註 |
|---|---|---|
| INTERSPEECH | 語音頂會，年會 | ISCA Archive 公開全文 |
| ICASSP | 訊號處理頂會，含語音 | IEEE Xplore，摘要公開 |
| ASRU | 語音辨識/理解專門會議 | 雙年一次 |
| SLT | Spoken Language Technology | 雙年一次 |

**次要/依題目加選**：EUSIPCO、APSIPA ASC、WASPAA、ACL/NAACL/EMNLP（若題目偏語言模型/對話）、ICML/NeurIPS/ICLR（若題目偏一般表示學習且有語音應用）、TASLP（期刊，非會議但審查嚴謹）。

**年份範圍**：預設近 2 年已放榜的 + 下一屆投稿季的 call/已公開 accepted list（若有）。使用者要查特定年份就照使用者說的。

## 搜尋策略（用 web_search / source_check 工具執行）

一次搜單一會議+關鍵字組合，多查詢並行，不要指望一個泛用查詢就找全：

```
"{關鍵字}" site:isca-archive.org Interspeech {年份}
"{關鍵字}" ICASSP {年份} paper
"{關鍵字}" ASRU {年份}
"{關鍵字}" SLT {年份}
"{關鍵字}" arXiv accepted Interspeech OR ICASSP {年份}
```

- 關鍵字要包含：任務名稱、方法類別、資料集名稱（如果題目鎖定特定資料集）
- 每個會議至少跑 2-3 個查詢變體（換同義詞、換任務說法），避免漏掉用不同術語但做同件事的論文
- 找到候選後，用 `fetch_content` 開摘要/論文頁確認任務、方法、資料集，不要只憑搜尋結果的一行摘要判斷相關性
- 如果搜到的是 arXiv 版本，標註「可能被接受於〔會議〕，請自行核實是否正式收錄」——不要替使用者斷言已收錄

## 相關性分類（沿用 `reading_log.md` 的分類語彙，保持一致）

| 類別 | 意思 |
|---|---|
| 可借 | 方法/成分可能借用到目前題目 |
| 是baseline | 目前或未來該和它比較的對象 |
| 競品 | 在做很接近的題目，要注意有沒有重疊或被超車 |
| 無關但有趣 | 不直接相關，但方法有意思 |
| 背景 | 補充理解現況/綜述性質 |

## 輸出：候選清單（不是論文報告）

用 `templates/paper_shortlist.md`。每篇一行，欄位：標題、作者(第一作者 et al.)、會議/年、連結、一句話主張（來自abstract，標明「摘要層級，未深讀」）、關係類別（上表五種之一）、建議理由、優先度（高/中/低）、已讀狀態（預設「未讀」）。

**篇數**：至少 8-15 篇讓使用者選，不要只給 2-3 篇——篩選的意義就是給選擇空間。寧可多列、標低優先度，也不要先幫使用者決定只給少數候選。

**排序**：依優先度排，但不要替使用者下結論「這篇最好」，只給判斷依據（例如「和目前Table1的baseline同資料集，近3個月發表，方法新穎度高」），讓使用者自己比較決定。

## AI 可以/不可以

可以：執行多輪搜尋、彙整候選清單、標相關性類別、提供排序依據、開摘要頁確認任務/方法/資料集是否相符。

不可以：
- 替使用者決定「報哪一篇」——那是要和partner/教授討論的事（見 `ask-professor-index.md`「這篇值得報嗎？」）
- 把清單裡任何一篇的摘要式描述當成已深讀的論文報告內容使用；深讀前的「一句話主張」只是初篩依據，正式報告要重新走 `paper-report.md` 五步流程並核對回論文原文
- 斷言某篇arXiv預印本已經正式被會議收錄，除非有官方accepted list佐證
- 跳過使用者的題目關鍵字，自己發散搜一個「看起來有趣」的主題

## 後續動作

1. 使用者從清單選定要深讀的 1 篇 → 進 `paper-report.md` 流程產生 13 頁投影片
2. 沒被選中但掃過的，可選擇性各補一行到 `reading_log.md`（標「掃過未深讀」，不要寫成已完成的淺讀五行格式——那格式代表讀過全文）
3. 如果清單裡發現和目前題目高度重疊的競品論文，提醒使用者這件事本身可能要帶去問教授（進度報告第8頁「要教授決定的事」或直接開 Issue）

## 怎麼核對

1. 關鍵字確實來自使用者現有檔案或使用者口述的題目，不是AI自己發散的泛用詞
2. 每篇候選都有連結，連結打得開、內容和描述相符
3. 「一句話主張」標明是摘要層級，沒有誇大成「已核對」
4. 篇數至少8-15篇，不是隨便湊2-3篇
5. 沒有替使用者斷言「這篇最好」或「這篇已正式收錄」
