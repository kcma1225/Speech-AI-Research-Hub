# 進度報告：group meeting（第 5 站）

來源：`guides/progress_report/group_meeting.md` v1.6。每週一次，從第 2 站（Table 1 審過）起到投稿。產學計畫參與者照報，不縮水（產學另有雙週報告，見 `industry-biweekly.md`）。

## 輸入（去使用者 repo 裡找）

- `notes/log.md` 本週小結（五格，見下）
- `_design.md` 的 Table 1 填格進度
- `idea_log.md` 最新一張 card
- 上週的 GitHub Issue（教授回饋）

## 投影片：固定 8 頁

| 頁 | 標題 | 內容 | 誰寫 |
|---|---|---|---|
| 1 | 問題定義 | 示意圖：題目在解什麼、原做法哪裡壞 | 沿用上週，變了才重畫 |
| 2 | Idea 或架構 | idea card 假設或 method figure，新成分標出 | 沿用上週，變了才重畫 |
| 3 | 對帳 | 上週說要做／實際做到，沒做到標紅 | AI 整理，使用者核對 |
| 4 | Table 1 現況 | 整張表，本週新填格加粗，空格留 `—`；右上角「距上次新數字：N 週」 | AI 整理，使用者核對 |
| 5 | 本週關鍵結果 | 一張圖/小表，只放最重要的一個 | AI 整理，使用者核對 |
| 6 | 卡住 | 三行：問題／試過什麼／卡在哪 | 使用者提供內容 |
| 7 | Idea card | 八格精簡版 | 使用者提供內容（不可由 AI 生 idea） |
| 8 | 下週與要問 | 下週要跑的 run 清單；要教授決定的事（編號）；本週淺讀 2 篇 | 使用者提供內容 |

**月度停損規則**：第 4 頁「距上次新數字」超過 4 週，meeting 固定要討論換題/砍格子/再給兩週——這不是可選項，模板要把這行顯著標出。

## 五格內容規則（對應 `notes/log.md` 週小結）

| 格 | 內容 | 第一行放什麼 |
|---|---|---|
| 1 對帳 | 上週原文貼過來、做到沒、沒做到的原因 | 上週教授回饋（從 Issue 引用） |
| 2 做了什麼 | 先數字後過程 | 「Table 1 填了 N 格」 |
| 3 卡住 | 問題／試過什麼／卡在哪 | 最卡的那一個 |
| 4 Card | 一張，八格；改過只講改了哪格 | card 編號與一句話標題 |
| 5 下週與要問 | 具體到 run；要教授決定的事 | 要教授決定的事 |

不報：看過沒結果的、失敗 run 一句帶過、「這週很忙」。

## 會議結構（固定順序，不可反）

進度報告（每人每週，10 分鐘報告+討論共30分）→ 論文報告（partner 輪流，20 分）。
進度報告內部順序：報進度 → 報 idea card → 在場每人預測教授會怎麼判 → 教授講判斷 → 討論。**第 4 步必須在第 2、3 步之後**。

## GitHub Issue 流程

1. 會前：開 Issue「`〔YYMMDD〕 進度`」，貼週小結五格＋投影片連結，label `progress`
2. 會中：教授回饋當場記錄在 Issue 留言（不要會後補）
3. 會後：有決定的同步進對應檔案（`_design.md` 審核紀錄、`idea_log.md` 狀態、`notes/log.md`、README「目前結果」），關 Issue
4. 下週新 Issue 第一行引用上週教授留言連結

Label 三種：`progress`（週報）、`question`（不急的問題）、`prof`（教授自己開）。教授需為 repo collaborator 才看得到 Issue。

## 檔案路徑慣例

```
reports/
  progress_〔YYMMDD〕.qmd
  progress_〔YYMMDD〕.html
```
檔名日期＝開會日期（YYMMDD），和 Issue 標題用同一天。

## 怎麼核對

1. 投影片每個數字在 `results.csv` 找得到那一行
2. 第 3 頁「上週說要做」和上週 Issue 第 5 格一字不差
3. 每個「教授說」在 Issue 留言找得到；決定都已同步到對應檔案
4. 演講稿自己念過一遍
