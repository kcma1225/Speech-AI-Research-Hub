# 審稿對帳（慣例）

來源：`conventions/review_reconciliation.md` v1。

## 時機

每次論文審稿意見回來（不論收或拒），**讀完意見的48小時內**，在改稿或rebuttal之前。

## 為什麼

審稿意見是整個lab最貴的教材，一年只有兩三次。不對帳，只會變成「這個審稿人不懂」的情緒。

## 怎麼做

1. 每條審稿意見拆成一列（一個審稿人通常3-8條）
2. 每條對回第2站的決策紀錄：打到哪一格——baseline選擇、資料集、公平比較、貢獻主張、分析、寫作
3. 填「當時想到了嗎」：
   - **想到了，決定不做**：寫當時理由；現在看理由站得住嗎
   - **想到了，沒做完**：時程問題，記下來給下次one-pager
   - **沒想到**：是哪一類盲點——文獻（prior work沒查到）、方法（副作用沒想）、評測（指標/資料集不夠）、主張（contribution講過頭）、寫作（審稿人看不懂）
4. 統計「沒想到」最多的一類，寫一句話進`reading_log.md`的「我容易漏的」
5. 下次group meeting用5分鐘報這張表，不報論文本身

## 表格模板

```markdown
# 審稿對帳：〔論文短名〕 〔會議 年份〕 結果：〔收／拒／分數〕

| # | 審稿人 | 意見（一句話摘要） | 打到決策紀錄哪一格 | 當時想到了嗎 | 類別 | 下次怎麼避免 |
|---|---|---|---|---|---|---|
| 1 | R1 | | | 想到決定不做／想到沒做完／沒想到 | 文獻／方法／評測／主張／寫作 | |

## 「沒想到」最多的一類：〔　〕
## 回填 reading_log「我容易漏的」：〔一句話〕
## 審稿人誤讀的（不是我們的錯，但表示哪裡寫不清楚）：〔　〕
```

最後一列很重要：審稿人「誤讀」在作者眼裡是審稿人問題，在下一篇論文裡是寫作問題。

## 檔案路徑

`notes/reviews_〔會議〕_〔年份〕.md`；「我漏的那一類」一行回填`reading_log.md`最上面。

## 和其他站的關係

對回第2站決策紀錄（決策紀錄要留著，不要投稿後就丟）；「我容易漏的」累積在`reading_log.md`，和審稿預測練習（paper-report.md §10）同一段；教授會看這張表調整挑card標準，partner也看（同一類盲點通常整組都有）。

## AI 禁寫部分

**「想到了嗎」「類別」的判斷必須使用者自己做**——這是誠實面對自己思考盲點的練習，AI 代判就失去意義。AI 可以幫忙整理表格格式、統計比例。

## 怎麼核對

1. 每條審稿意見都對回決策紀錄某一格（找不到對應格要誠實標出，不是硬套）
2. 「沒想到」類別統計準確
3. 「我容易漏的」已回填reading_log.md
4. 審稿人誤讀的部分單獨列出，和「我方錯誤」區分
