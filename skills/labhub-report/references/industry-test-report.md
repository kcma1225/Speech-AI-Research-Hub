# 產學研究測試報告（給產業方工程師）

來源：`guides/industry_project/industry_track.md` §6、§7。驗收測試達標、或每輪改善完成後交一版。讀者是產業方工程師，標準只有一個：**工程師不用問你，就能重跑出報告裡的數字，並知道它在哪裡會失效。**

Quarto 一次 render 出 html 與 docx（docx可另存PDF）。檔名 `report/test_report_v〔N〕.qmd`，每次交付版本號加一。

## 固定 9 節

| 節 | 寫什麼 |
|---|---|
| 1 摘要 | 半頁：需求一句；每個驗收指標一行（門檻/結果/達標與否）；建議 |
| 2 需求與驗收指標 | 引用需求規格表版本號；指標定義與正規化規則放附錄 |
| 3 測試資料與環境 | 資料描述（筆數/時數/切分/標註）；硬體；軟體版本（完整版本見uv.lock） |
| 4 比較的方法 | 測了哪些方法、為什麼選（附論文）、各自實作與權重版本 |
| 5 結果 | 驗收集主表；公開benchmark對照（和論文數字對上）；代價（RTF/記憶體/參數量） |
| 6 錯誤分析 | 類別與比例、代表樣本、人聽得出但模型錯的比例 |
| 7 限制與已知問題 | 在什麼條件下會失效；哪些條件沒測到 |
| 8 重現步驟 | 程式位置、`uv sync`、一行指令重跑驗收、預期得到的數字 |
| 9 給工程師的建議 | 延伸或部署注意事項；不寫成產品設計 |

## 鐵律

- **第5節公開benchmark對照不能省**——這是工程師相信實作沒錯的依據，和第3站「復現對上才有資格說自己方法贏」同一道理
- **第7節要誠實**，把錯誤分析看到的失敗類別全部寫進來
- **交出去之前**，group另一人照第8節在乾淨環境（新clone、新uv sync）重跑一次，數字對上才交

## 交付包（`delivery/`）

| 放 | 不放 |
|---|---|
| 研究測試報告（html/docx/PDF） | 研究repo的notes/（idea log、論文筆記、日誌） |
| 重跑所需程式（模型程式/config/驗收腳本） | 還沒發表的方法（要不要交由教授決定） |
| pyproject.toml、uv.lock、.python-version | lab其他人程式 |
| results用到的結果（acceptance.csv與相關results.csv列） | 金鑰、帳號、機器登入資訊 |
| README：安裝/怎麼跑/預期數字 | 產業方以外、授權不允許轉交的資料 |
| 授權表：每個用到的預訓練模型/資料集/套件授權 | |

- **從研究repo複製需要的檔案，不是把研究repo給出去**
- **授權表一定要有**：逐項查原始授權頁（請自行查證，不要讓AI查），查不到標「未確認」交教授判斷
- checkpoint要不要交、怎麼交，問教授
- 交付前乾淨環境照README跑一次；打git tag `delivery-v〔N〕`，和報告版本號一致

## AI 可以/不可以

不可以：用AI生報告內容（含需求與產業方資料結果）——照模板自己填；讓AI查授權頁。
可以：協助排版、檢查格式完整性、潤飾不含產業方資料的敘述段落。

## 怎麼核對

1. 第5節公開benchmark對照有完整數字
2. 第7節列出所有已知失敗類別，沒有隱藏
3. group另一人乾淨環境重跑第8節步驟，數字一致
4. 交付包裡沒有notes/、沒有金鑰
5. 授權表每一列都填了（含「未確認」標記，不是空白）
6. git tag版本號和報告版本號一致
